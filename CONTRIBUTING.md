# Участие в разработке

## Процесс

1. Создайте ветку от `main`: `feature/<кратко>`, `fix/<кратко>` или
   `chore/<кратко>`.
2. Внесите изменения; для новой логики добавьте юнит-тесты в `tests/`.
3. Перед коммитом выполните `make check` — он запускает сборку с `-Werror`,
   тесты, санитайзеры и проверку форматирования.
4. Откройте pull request. CI должен быть зелёным; изменения проходят ревью.

## Коммиты

Используется [Conventional Commits](https://www.conventionalcommits.org/):

```
<тип>(<область>): <краткое описание>

<необязательное тело: что и почему, а не как>
```

Типы: `feat`, `fix`, `refactor`, `test`, `docs`, `build`, `ci`, `chore`.
Области: имена модулей (`input`, `terminal`, `ui`, …) или `make`, `ci`.

Примеры:

```
feat(input): распознавать X10-отчёты мыши
fix(ui): устранить дрожание времени окончания на ±1 с
refactor(terminal): инкапсулировать состояние raw-режима
```

## Стиль кода

Форматирование задаётся `.clang-format` и проверяется в CI; вручную
выравнивать ничего не нужно — `make format`.

Основные правила:

- Стандарт C11, только POSIX; без расширений компилятора.
- Публичные идентификаторы с префиксом `ww_` (функции, типы) или `WW_`
  (макросы, константы enum). Полная таблица — в
  [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).
- Все функции, не входящие в публичный API модуля, объявляются `static`.
- Указатели на неизменяемые данные — `const`. Параметры-выходы идут
  последними.
- Функции, которые могут не выполниться, возвращают `ww_status_t`; коды
  ошибок не смешиваются с полезными значениями.
- Нет «магических чисел»: константы именуются через `#define` или `enum`.
- Комментарии объясняют **почему**, а не **что**. Публичные заголовки
  документируются в стиле Doxygen (`@brief`, `@param`, `@return`).
- Логика без побочных эффектов выделяется в чистые функции и покрывается
  тестами; работа с ОС локализуется в `terminal` и `clock`.

## Тесты

- Каркас — `tests/ww_test.h`, внешних зависимостей нет.
- Один файл `tests/test_<модуль>.c` на модуль; набор регистрируется в
  `tests/suites.h` и вызывается из `tests/test_main.c`.
- Имена тестов описывают поведение: `sgr_mouse_release_is_ignored`.
- Тесты не зависят от окружения: часовой пояс фиксируется (`TZ=UTC`),
  реальное время в утверждениях не используется.

## Definition of Done

- [ ] `make check` проходит локально.
- [ ] Новая логика покрыта тестами.
- [ ] Обновлены `README.md` / `docs/ARCHITECTURE.md`, если изменилось
      поведение или структура.
- [ ] Добавлена запись в `CHANGELOG.md` (раздел *Unreleased*).
