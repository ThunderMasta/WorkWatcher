# Архитектура WorkWatcher

## Обзор

WorkWatcher — однопоточное консольное приложение. Главный цикл поочерёдно
выполняет «фазы» (режим **Работа** или **Дом**): пока фаза активна, экран
перерисовывается с периодом `WW_REFRESH_INTERVAL_US`; событие ввода
завершает фазу, её длительность засчитывается в счётчик режима, и цикл
переходит к следующей фазе.

## Модули и зависимости

```
main ──► app ──► tracker
  │       │  ├──► clock
  │       │  ├──► input
  │       │  ├──► terminal ──► status
  │       │  └──► ui ──► tracker
  ├──► terminal
  ├──► status
  └──► version

config ◄── (все модули, только макросы)
```

Стрелка `A ──► B` означает «A включает заголовок B». Циклических
зависимостей нет.

| Модуль     | Тип            | Состояние                      | Тестируемость          |
|------------|----------------|--------------------------------|------------------------|
| `config`   | макросы        | —                              | —                      |
| `status`   | чистый         | —                              | юнит                   |
| `clock`    | обёртка над ОС | `ww_stable_clock_t` (явное)    | юнит (частично)        |
| `tracker`  | чистый         | `ww_tracker_t` (явное)         | юнит                   |
| `input`    | чистый         | —                              | юнит                   |
| `ui`       | смешанный      | —                              | юнит (форматирование)  |
| `terminal` | обёртка над ОС | статическое, единственное      | ручное / smoke в CI    |
| `app`      | оркестратор    | `ww_app_t` (явное)             | ручное                 |
| `main`     | точка входа    | —                              | smoke в CI             |

Принцип: вся логика, которую можно проверить без терминала и часов,
вынесена в чистые функции с явными входами и выходами. Побочные эффекты
(чтение stdin, запись в stdout, `termios`, сигналы) локализованы в
`terminal` и в двух функциях `ui`.

## Соглашения по именованию

| Сущность            | Стиль                         | Пример                        |
|---------------------|-------------------------------|-------------------------------|
| Публичная функция   | `ww_<модуль>_<глагол>`        | `ww_tracker_accumulate`       |
| Тип                 | `ww_<имя>_t`                  | `ww_input_event_t`            |
| Константа enum      | `WW_<ТИП>_<ЗНАЧЕНИЕ>`         | `WW_INPUT_TOGGLE`             |
| Макрос конфигурации | `WW_<ИМЯ>`                    | `WW_WORKDAY_SECONDS`          |
| Внутренняя функция  | `static`, без префикса        | `parse_sgr_mouse`             |
| Глобальная static   | префикс `g_`                  | `g_saved_termios`             |
| Include guard       | `WORKWATCHER_<ФАЙЛ>_H`        | `WORKWATCHER_TRACKER_H`       |

## Ключевые решения

### Два вида часов

- **Длительности** (`ww_clock_monotonic_seconds`) считаются по
  `CLOCK_MONOTONIC`, поэтому перевод системных часов не искажает счётчики.
- **Время окончания** требует настенных часов, но не должно «прыгать» при
  переводе времени. `ww_stable_clock_t` фиксирует пару (настенное,
  монотонное) при старте и дальше экстраполирует по монотонным часам.

### Однократное округление

Момент окончания вычисляется как `now + remaining` в `double` и лишь затем
приводится к `time_t`. Два независимых отбрасывания дробной части давали бы
дрожание ±1 с (см. тест `finish_line_rounds_once`).

### Разбор ввода как чистая функция

`terminal` читает «всё, что пришло одним нажатием» (первый байт плюс хвост
в течение `WW_KEY_TAIL_US`) и передаёт буфер целиком в `ww_input_parse`.
Парсер понимает отчёты мыши в кодировках SGR (`ESC [ < Cb;Cx;Cy M/m`) и
X10 (`ESC [ M Cb Cx Cy`), игнорирует отпускания, прокрутку и движение, а
управляющий символ `Ctrl+C` (0x03) трактует как запрос на завершение. Он
доходит до приложения байтом только потому, что в raw-режиме отключён
`ISIG` (иначе драйвер терминала превратил бы его в `SIGINT`). Комбинации с Cmd
перехватывает само приложение терминала — программа их не видит. Всё это покрыто тестами в `tests/test_input.c`.

### Raw-режим и сигналы

В raw-режиме отключён `ISIG`, поэтому `Ctrl+C` приходит приложению байтом
`0x03`, а не сигналом — это позволяет корректно завершить фазу и вывести
сводку. Обработчики `SIGINT`/`SIGTERM`/`SIGHUP` нужны для внешних сигналов
(`kill`, закрытие окна) и используют только async-signal-safe вызовы:
`write`, `tcflush`, `tcsetattr`, `_exit`. Атрибуты применяются с `TCSANOW`,
а не `TCSAFLUSH`: последний ждёт, пока терминал заберёт весь вывод, и в
обработчике сигнала может заблокировать завершение процесса.

Состояние терминала хранится в единственном статическом экземпляре внутри
`terminal.c` — это осознанное исключение из правила «без глобального
состояния», поскольку обработчик сигнала не получает пользовательского
контекста.

### Вывод без мерцания

Экран очищается один раз при старте. Каждый кадр адресует строки явно
(`ESC [ n ; 1 H`) и очищает их (`ESC [ 2 K`), не трогая остальной экран.

## Расширение

- **Новый режим**: добавить значение в `ww_mode_t` до `WW_MODE_COUNT`,
  обновить `ww_mode_next` и подписи в `ui.c`.
- **Новая горячая клавиша**: добавить событие в `ww_input_event_t`,
  распознавание в `input.c`, реакцию в `app.c`; покрыть тестом.
- **Новый параметр**: объявить в `config.h` с `#ifndef`, чтобы его можно
  было переопределить флагом компилятора.
